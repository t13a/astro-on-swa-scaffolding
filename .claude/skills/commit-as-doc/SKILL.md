$ARGUMENTS で指定された対象をコミットする。引数が省略された場合は、ステージ済みまたは未ステージの変更を確認してコミット対象を判断すること。

以下の手順で進める。

## 1. 差分の確認

`git diff` および `git status` で変更内容を把握する。

## 2. コミットメッセージの作成

コミットメッセージはプロジェクトのドキュメントとして機能する。以下の規約に従うこと。

### 原則

ソースコードの変更内容（差分で読み取れるもの）は省略し、**差分だけでは伝わらない情報**を記載する。

### 記載すべき内容

- **設計判断と理由** — なぜその方法を選んだか、検討して却下した代替案があればそれも
- **手動手順** — `npm install`、環境変数の設定、DB マイグレーションなど、コード変更から再現できない操作
- **外部参照** — 関連するドキュメントや Issue へのリンク

### フォーマット

- 件名: 日本語で簡潔に。体言止めまたは動詞終わり（例: 「〜を追加」「〜に分離」）
- 本文: Markdown（リスト、コードブロック）で構造化する
- 本文の書き出しは変更の概要を1〜2文で。その後に設計判断や手動手順を箇条書きで続ける

### 例

```
利用者向けお知らせ取得 API とトップページへの表示を追加

管理者用 `/api/management/announcements` (CRUD) に対して、利用者向けの
読み取り専用エンドポイント `/api/announcements` を追加する。

- GET のみ。認証不要、DB ミドルウェアのみ適用。
- `published = true` のレコードだけを `createdAt` 降順で返す。
```

```
トップページのクライアントサイド処理を Astro コンポーネントに分離

Greeting と Announcements をカスタム要素ベースの Astro コンポーネントとして切り出す。

Shadow DOM は使わない。Astro がサーバーサイドで生成した HTML をカスタム要素が
そのまま引き継ぐため、Light DOM である必要がある。
```

## 3. コミットの実行

ユーザーにメッセージを確認してもらい、承認後にコミットする。
